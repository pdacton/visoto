{{ tHTML "page.media.whyOfcom" "That pairing is not accidental. OFCOM both regulates broadcasting — awarding licences, distributing the reception fee, monitoring whether public-service obligations are met — and oversees telecommunications infrastructure. {{ t "page.media.followTheMoney" "Where the advertising went" }}

{{ tHTML "page.media.advertisingIntro" "The clearest series in this theme is also the bleakest for anyone who works in Swiss media: advertising revenue by media genre, year by year. It shows the press still the largest single category by revenue, but falling steadily — and online advertising, the thing that was supposed to replace it, sitting at less than half the press figure and not growing." }}

{{ tHTML "page.media.advertisingNuance" "The reason is that this cube measures advertising booked with Swiss media. The money leaving newspapers has not moved to Swiss news websites; it has largely left the domestic market altogether for global platforms that OFCOM does not survey. Read the online column as \"online advertising captured by Swiss publishers\", not as the size of digital advertising in Switzerland." }}

{{ t "page.media.theCollection" "Five hundred cubes of media research" }}

{{ tHTML "page.media.collectionIntro" "OFCOM's media graph is large and unusually granular. Beyond audience figures it carries programme analyses — studies that code broadcast output by topic and format, so it is possible to ask what proportion of a regional radio station's airtime was regional news rather than music. That level of detail exists because private broadcasters receiving a share of the reception fee carry a performance mandate, and the analyses are how compliance is measured." }}

{{ tHTML "page.media.collectionSpread" "The families below span the whole media landscape: Mediapulse audience measurement for television, reach and programme structure for SRG and commercial radio, print readership by age, online media by topic and genre, and the revenue structure of the public broadcaster itself." }}

# Groups the 533 cubes into families by stripping the trailing version number. # # ?rowsPerCube is MAX rather than SUM on purpose: the versions of a family are # re-publications of the same dataset, so summing them would report a collection # several times larger than it is. MAX gives the size of one release. # # ?family is a plain string, not an IRI — there is no resource representing a # family, only the individual versioned cubes. SELECT ?family ?versions ?rowsPerCube WHERE { { SELECT ?family (COUNT(DISTINCT ?cube) AS ?versions) (MAX(?n) AS ?rowsPerCube) WHERE { { SELECT ?cube (COUNT(?obs) AS ?n) WHERE { GRAPH <https://lindas.admin.ch/ofcom/cube> { ?cube a cube:Cube ; cube:observationSet/cube:observation ?obs . } } GROUP BY ?cube } BIND (REPLACE(STR(?cube), "^https://communication.ld.admin.ch/ofcom/([^/]+)/.*$", "$1") AS ?family) } GROUP BY ?family } } ORDER BY DESC(?rowsPerCube)

{{ tHTML "page.media.collectionCaveat" "The 533 cubes are far fewer datasets than that number suggests — most families exist in eight to fourteen versions, each a separate cube IRI ending in a number, and only the highest is current. {{ t "page.media.broadband" "The pipe into the building" }}

{{ tHTML "page.media.ngaIntro" "The NGA dataset — for next-generation access — is the national broadband coverage survey, and its unit of measurement is unusually concrete: not households or people but premises, the individual buildings a network could be connected to. For every municipality it reports how many premises can obtain a given service, expressed both as an absolute count and as a percentage." }}

{{ tHTML "page.media.ngaConditions" "Coverage is not one number but thirteen, one per condition. Seven are download-speed thresholds from 10 Mbit/s up to a gigabit, four are upload thresholds, and three name the physical medium — fibre, coaxial cable or copper. Reading them as a ladder shows where the network thins out: near-universal at basic broadband, still strong at 100 Mbit/s, and dropping sharply once gigabit service is the requirement." }}

# One row per coverage condition, aggregated over all municipalities. # # ?avgCoverage is the mean of the per-municipality percentages — it weights a # 200-premises alpine commune the same as the city of Zurich. ?premisesCovered # sums the absolute counts instead, which is the population-weighted view. The two # deliberately disagree (fibre averages ~44% of municipalities but reaches ~57% of # premises) because fibre is built where the buildings are. SELECT ?condition ?avgCoveragePct ?premisesCovered ?premisesTotal WHERE { { SELECT ?condition (ROUND(AVG(xsd:decimal(?pct)) * 10) / 10 AS ?avgCoveragePct) (SUM(xsd:integer(?cov)) AS ?premisesCovered) (SUM(xsd:integer(?tot)) AS ?premisesTotal) WHERE { GRAPH <https://lindas.admin.ch/ofcom/nga> { ?obs <https://communication.ld.admin.ch/ofcom/nga/cond> ?condition ; <https://communication.ld.admin.ch/ofcom/nga/pctcov> ?pct ; <https://communication.ld.admin.ch/ofcom/nga/abscond> ?cov ; <https://communication.ld.admin.ch/ofcom/nga/abstot> ?tot . } } GROUP BY ?condition } } ORDER BY DESC(?premisesCovered)
{{ template "sparqlAsyncTable" (dict "queryId" "mediaBroadbandLadder" "title" (t "card.broadbandLadder" "Broadband coverage by service condition") "icon" "signal") }}

{{ tHTML "page.media.ngaGap" "Note the disagreement between the two coverage columns. Averaged across municipalities, fibre reaches around forty-four per cent; counted by premises it reaches well over half. The gap is the rural–urban divide stated arithmetically — fibre is built where the buildings already are, so it covers many people in few places." }}

# ?canton stays an IRI so the backend resolves and links it. # # Restricted to ONE condition (gigabit download) because the cube holds thirteen # rows per municipality — without the filter each canton's figures are averaged # across every speed tier at once, which is meaningless. SELECT ?canton ?gigabitPct ?premisesCovered ?premisesTotal WHERE { { SELECT ?canton (ROUND(SUM(xsd:integer(?cov)) * 1000 / SUM(xsd:integer(?tot))) / 10 AS ?gigabitPct) (SUM(xsd:integer(?cov)) AS ?premisesCovered) (SUM(xsd:integer(?tot)) AS ?premisesTotal) WHERE { GRAPH <https://lindas.admin.ch/ofcom/nga> { ?obs <https://communication.ld.admin.ch/ofcom/nga/ktnr> ?canton ; <https://communication.ld.admin.ch/ofcom/nga/cond> "DOWN >= 1000" ; <https://communication.ld.admin.ch/ofcom/nga/abscond> ?cov ; <https://communication.ld.admin.ch/ofcom/nga/abstot> ?tot . } } GROUP BY ?canton } } ORDER BY DESC(?gigabitPct)

{{ tHTML "page.media.ngaCaveat" "The whole dataset is a single monthly snapshot, not a time series — every observation carries the same month, so this shows the state of the network now rather than how it got here. Note also that coverage means a premises could subscribe, not that anyone has: this is availability, not take-up." }}

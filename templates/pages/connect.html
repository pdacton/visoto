Visoto ships an MCP server that lets AI assistants explore the same SPARQL endpoints you see here — discover classes, search by label, run queries — and link their answers back to Visoto's visualizations. Connect it to your own assistant and ask questions there, using your own subscription. The built-in Resource Assistant stays available as the zero-setup default.

Most AI services require a paid plan to add custom connectors, and can only reach the server when it is publicly accessible over HTTPS.

Your MCP server URL

Transport: streamable HTTP · read-only · no authentication or API key required.

Set it up in your assistant

  • Claude
  • ChatGPT
  • Mistral Le Chat
  • Qwen
  • OpenRouter
  • Apertus

Requires a Claude Pro plan or higher.

  1. Open claude.ai → Settings → Connectors
  2. Click Add custom connector, name it Visoto and paste the MCP URL above
  3. In a chat, open the search & tools menu and enable the Visoto connector

Claude Desktop — connectors are account-level: added on claude.ai, it appears in the desktop app automatically.

Claude Code — one command:

claude mcp add --transport http visoto {{ .BaseURL }}/mcp

Requires ChatGPT Plus or higher; custom connectors live behind Developer mode.

  1. Open Settings → Connectors → Advanced and enable Developer mode
  2. Create a new connector and paste the MCP URL above (no authentication)
  3. Enable the connector in the chat's tools menu — re-enable it per chat if needed

ChatGPT only accepts remote HTTPS MCP servers, so it must reach this instance's public URL.

  1. In Le Chat, open the connectors panel from the sidebar
  2. Click Add a custom connector and paste the MCP URL above (leave the API key empty)
  3. Save, then enable the connector in your chat

MCP support lives in the Qwen Chat desktop app.

  1. Open MCP settings in Qwen Chat Desktop
  2. Click Add MCP and paste the MCP URL above
  3. Enable the server in your chat

For advanced users. OpenRouter's own chat can't consume external MCP servers — instead, use OpenRouter as the model backend (GPT, Gemini, DeepSeek, and hundreds more with one key) inside an MCP-capable client.

  1. Create an API key at openrouter.ai/keys
  2. Add it to an MCP-capable chat client (e.g. LibreChat or Cherry Studio) as an OpenAI-compatible provider
  3. Register the MCP URL above as a tool/MCP server in that client

Apertus, the Swiss open-source model by EPFL/ETH Zürich, has no first-party chat app with MCP connectors — use the same client pattern as the OpenRouter tab.

  1. Get access to an OpenAI-compatible Apertus endpoint (e.g. via the Public AI inference utility or Swisscom's Swiss AI platform)
  2. Add it as a provider in an MCP-capable client (see the OpenRouter tab for candidates)
  3. Register the MCP URL above as a tool/MCP server in that client

Privacy & trust — the server is read-only: it can list endpoints and prefixes, discover classes and properties, and run SPARQL SELECT queries against the configured public endpoints. It holds no account data and requires no key.

These six are just walkthroughs — any MCP-capable client works.

{{ t "page.culture.aboutThisTheme" "About this theme" }}

{{ tHTML "page.culture.intro" "This is the largest theme in LINDAS by a wide margin, and the least like the others. Where energy or agriculture publish measurements, the Swiss Federal Archives publish descriptions: an archival finding aid is a nested account of what exists, where it sits in the holdings, and what it is about. The Swiss National Library adds the register of institutions that hold such material across the country." }}

{{ tHTML "page.culture.ricIntro" "The archive is modelled in Records in Contexts (RiC-O), the International Council on Archives' ontology — not in the cube vocabulary used almost everywhere else on the platform. That choice is the single most important thing to know before querying it. RiC is built for description rather than aggregation: its central idea is that a record is only meaningful through its context, so the relationships (what includes what, who held it, what activity produced it) carry as much of the meaning as the titles do." }}

{{ t "page.culture.shapeOfAnArchive" "The shape of an archive" }}

{{ tHTML "page.culture.hierarchyIntro" "Archival description is strictly hierarchical, and the levels have names archivists have used for a century. Everything nests downward from the archive itself through main departments and fonds to the individual dossier, and each level is a RecordSet carrying a hasRecordSetType that says which rung it occupies. Almost the entire volume sits at the bottom: dossiers outnumber every other level combined by roughly ten to one." }}

# ?type stays an IRI so the backend resolves and links it. # # SAMPLE on the name is REQUIRED, not cosmetic: ric:name is untagged and repeated # once per language (Dossier / Dossier / Dossier / Dossier, Serie / Série / Serie), # so a plain ?typeName in the SELECT multiplies every row three or four times. # There is no lang() filter available to fix it — the literals carry no tags at all. SELECT ?type ?level ?recordSets WHERE { { SELECT ?type (COUNT(?rs) AS ?recordSets) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?rs a <https://www.ica.org/standards/RiC/ontology#RecordSet> ; <https://www.ica.org/standards/RiC/ontology#hasRecordSetType> ?type . } } GROUP BY ?type } { SELECT ?type (SAMPLE(?n) AS ?level) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?type <https://www.ica.org/standards/RiC/ontology#name> ?n . } } GROUP BY ?type } } ORDER BY DESC(?recordSets)

{{ tHTML "page.culture.divisionsIntro" "At the very top the archive divides into eight main departments, and they are periods of Swiss history rather than subjects. The Archiv der Helvetik covers the short-lived Helvetic Republic of 1798–1803, followed by the Mediation and the Tagsatzung; the bulk of everything sits under the Archiv des Schweizerischen Bundesstaates, the federal state from 1848 onward. Deposits and donations from private hands form their own division alongside them." }}

{{ t "page.culture.whatRecordsDescribe" "What the records describe" }}

{{ tHTML "page.culture.recordsIntro" "Beneath the record sets sit the records themselves, and they are richer than a catalogue entry. Alongside a title and a reference code, a record can carry a scope and content note, an author, a publisher, a named cameraman, a physical format and a subject descriptor. That mix is a clue to what a large part of this archive actually holds: not only paper files but broadcast material — television and radio items deposited by the public broadcaster, with running times, colour information and tape formats recorded in the format field." }}

{{ tHTML "page.culture.accessIntro" "Every record also carries an access rule via isAssociatedWithRule. Archival access in Switzerland is governed by protective periods — normally thirty years, longer for files touching personal data — so this property is what separates a description you can read from a document you can actually request. The description is public even when the document is not yet." }}

# Which descriptive fields are actually populated across the 263k records. # Counting property usage rather than values: this is a profile of how completely # the archive is described, which is the useful thing to know before querying it. # # Bounded deliberately to a hand-picked property list — an unrestricted # ?record ?p ?o GROUP BY ?p over 263k records with ~20 properties each is a # multi-million-row scan and times out. SELECT ?field ?records WHERE { { SELECT ("Scope and content" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://www.ica.org/standards/RiC/ontology#scopeAndContent> ?v . } } } UNION { SELECT ("Physical form" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/form> ?v . } } } UNION { SELECT ("Technical format" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/format> ?v . } } } UNION { SELECT ("Subject descriptor" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/thema> ?v . } } } UNION { SELECT ("Author" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/author> ?v . } } } UNION { SELECT ("Publisher" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/publisher> ?v . } } } UNION { SELECT ("Geographic / temporal coverage" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/coverture> ?v . } } } UNION { SELECT ("Camera / crew credit" AS ?field) (COUNT(?r) AS ?records) WHERE { GRAPH <https://lindas.admin.ch/sfa/ais> { ?r a <https://www.ica.org/standards/RiC/ontology#Record> ; <https://schema.ld.admin.ch/involve> ?v . } } } } ORDER BY DESC(?records)

{{ t "page.culture.whoHoldsWhat" "Who holds what" }}

{{ tHTML "page.culture.isilIntro" "An ISIL is the international standard identifier for a library or archive — CH-000018-2 is the Federal Archives itself — and the National Library maintains the Swiss register of them. It reaches well beyond national institutions: municipal libraries, school mediatheques, parish archives, corporate collections and theatre archives all carry one. For many entries the register records a founding year, the size of the holdings, a prose administrative history and a description of what the collection contains." }}

{{ tHTML "page.culture.isilJoin" "The identifier is what makes the two archival graphs join. Every record in the Federal Archives points through hasOrHadHolder at an ISIL resource, so a description and the institution holding it are linked by a shared identifier rather than a name string — the same pattern the energy theme uses for company UIDs." }}

# ?isil stays an IRI so the backend resolves the institution and links it. # # libraryMaterials is a plain literal holding count, present on only a subset of # the register — the join is deliberately NOT optional here so the table shows the # institutions that actually report their size, sorted by it. SELECT ?isil ?holdings ?foundedIn ?code WHERE { GRAPH <https://lindas.admin.ch/nl/isil> { ?isil a <https://schema.ld.admin.ch/Isil> ; <https://schema.ld.admin.ch/libraryMaterials> ?holdings ; schema:termCode ?code . OPTIONAL { ?isil schema:validFrom ?foundedIn } } } ORDER BY DESC(xsd:integer(?holdings))

{{ tHTML "page.culture.isilCaveat" "The holdings figures are self-reported and not on a common basis — some institutions count volumes, others items or linear metres — so treat the ordering as indicative rather than a ranking. {{ t "page.culture.stapfer" "A school survey from 1799" }}

{{ tHTML "page.culture.stapferIntro" "The Stapfer Enquête is the oldest dataset on the platform and the most vivid. In 1799 Minister of Arts and Sciences Philipp Albert Stapfer sent a questionnaire to every schoolmaster in the Helvetic Republic, asking who taught, who attended, what was taught and on what the school lived. Thousands of replies survive, and they have been transcribed into a queryable dataset — the closest thing Switzerland has to a census of its schools at the moment the modern state began." }}

{{ tHTML "page.culture.stapferSeasons" "One detail in the structure tells you almost everything about rural life in 1799: attendance is recorded separately for winter and summer, and separately for boys and girls. Summer figures are routinely a fraction of winter ones, because in summer children worked the fields. The seasonal gap in this data is a measurement of agricultural labour, not of schooling." }}

# This graph uses the OLD W3C data cube vocabulary (qb:Observation from # purl.org/linked-data/cube), NOT cube.link like the rest of the platform — # a cube:Observation pattern here matches nothing at all. # # The school NAME lives on the linked Schule resource, not on the observation, # so the extra hop through ?school is required to get a readable label. # Summer columns are OPTIONAL: many schools reported only a winter term. SELECT ?schoolName ?boysWinter ?girlsWinter ?boysSummer ?girlsSummer ?observation WHERE { GRAPH <https://lindas.admin.ch/sfa/stapfer_enquete> { ?observation a <http://purl.org/linked-data/cube#Observation> ; <https://education.ld.admin.ch/stapfer_enquete/schule> ?school ; <https://education.ld.admin.ch/stapfer_enquete/schueler-anzahl-maennlich-winter> ?boysWinter ; <https://education.ld.admin.ch/stapfer_enquete/schueler-anzahl-weiblich-winter> ?girlsWinter . ?school <https://education.ld.admin.ch/stapfer_enquete/schule-name> ?schoolName . OPTIONAL { ?observation <https://education.ld.admin.ch/stapfer_enquete/schueler-anzahl-maennlich-sommer> ?boysSummer } OPTIONAL { ?observation <https://education.ld.admin.ch/stapfer_enquete/schueler-anzahl-weiblich-sommer> ?girlsSummer } } } ORDER BY ?schoolName
{{ template "sparqlAsyncTable" (dict "queryId" "cultureStapferAttendance" "title" (t "card.stapferAttendance" "Pupils per school, winter and summer 1799") "icon" "graduation-cap") }}

{{ tHTML "page.culture.stapferCaveat" "These are transcriptions of a 226-year-old manuscript source, and they read like it. A handful of entries carry implausible figures — one school reports over a thousand boys against ninety-five girls — which reflect the original return or its transcription rather than the village. Sort by any column and the outliers surface immediately; treat them as documents, not measurements." }}

{{ t "page.culture.stateAccounts" "The federal budget since 1850" }}

{{ tHTML "page.culture.stateAccountsIntro" "The Federal Archives also publish something that is not a finding aid at all: the state accounts, the federal budget and closing accounts as a continuous cube reaching back to 1850 — two years after the founding of the federal state. The same figures are cut four ways, one cube family per view: by domain, by office, by function and by category." }}

{{ tHTML "page.culture.budgetVsAccounts" "Each row is tagged with a report type, and the distinction matters more than it first appears: Voranschlag is the budget as planned, Rechnung the accounts as they closed. Both are present for the same year and the same line, so the gap between what the Confederation intended to spend and what it actually spent is directly queryable across 175 years. The earliest years are recognisably a different state — in 1850 the largest items are the postal administration, customs duties and the military department." }}

# Rooted in ONE cube version on purpose: this family has 11 versioned cubes that # share dimension IRIs, so an unrooted pattern would sum the same 11,506 rows # eleven times over. Always take the highest-numbered cube unless comparing releases. # # Two traps here: # 1. time:year is typed xsd:gYear — a bare "1850" string matches nothing. # 2. domain names are untagged and repeated per language, so the lang(?n)="" test # keeps a single row; there are no language tags to filter on properly. # RT2 = Rechnung / Comptes (accounts as closed), as opposed to RT1 (budget). SELECT ?year ?domainName ?amountCHF ?observation WHERE { GRAPH <https://lindas.admin.ch/sfa/cube> { <https://culture.ld.admin.ch/sfa/StateAccounts_Domain/12> cube:observationSet/cube:observation ?observation . ?observation <http://www.w3.org/2006/time#year> ?year ; <http://schema.org/amount> ?amountCHF ; <https://culture.ld.admin.ch/sfa/StateAccounts_Domain/domain> ?domain ; <https://culture.ld.admin.ch/sfa/StateAccounts_Domain/reporttype> <https://culture.ld.admin.ch/sfa/StateAccounts_Domain/12/ReportType/RT2> . ?domain schema:name ?domainName . FILTER (?year >= "1850"^^xsd:gYear && ?year <= "1875"^^xsd:gYear) FILTER (xsd:decimal(?amountCHF) > 0) FILTER (lang(?domainName) = "") } } ORDER BY ?year DESC(xsd:decimal(?amountCHF))

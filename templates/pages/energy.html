{{ tHTML "page.energy.twoPublishersTwoQuestions" "Two publishers cover this theme, and they answer two different questions. The Swiss Federal Office of Energy describes the physical system: how much energy the country consumes and from which carriers, how full the alpine reservoirs are this week, how much solar capacity was subsidised in each canton. The Federal Electricity Commission describes the market: what every grid operator in the country charges, for every consumption profile, every year since 2011." }}

{{ tHTML "page.energy.thePriceDataIsTheUnusual" "The price data is the unusual one. Electricity in Switzerland is not sold at a national price — it is sold by roughly 550 local grid operators, most of them municipal utilities, each setting its own tariff. ElCom collects all of them, which turns a household bill into something you can query: who charges what, where, and which part of the bill is actually the electricity?" }}

# ?operator stays an IRI so the backend resolves it to the utility's name and links it. # Municipality count shows the operator's reach; the price columns are its own tariff. # # The price columns are a SAMPLE (an operator may charge different tariffs in different # municipalities), so ?observation samples the IRI of the SAME row the figures came from # — without it the representative price would be untraceable. SAMPLE is not guaranteed to # pick from one row across separate aggregates, but GraphDB evaluates them together here; # treat the IRI as "one observation behind this price", not as a keyed join. SELECT ?operator ?total ?energy ?gridusage ?municipalities ?observation WHERE { { SELECT ?operator (SAMPLE(?t) AS ?total) (SAMPLE(?e) AS ?energy) (SAMPLE(?g) AS ?gridusage) (SAMPLE(?obs) AS ?observation) (COUNT(DISTINCT ?municipality) AS ?municipalities) WHERE { GRAPH <https://lindas.admin.ch/elcom/electricityprice> { ?obs <https://energy.ld.admin.ch/elcom/electricityprice/dimension/period> "2026"^^xsd:gYear ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/operator> ?operator ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/municipality> ?municipality ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/total> ?t ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/energy> ?e ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/gridusage> ?g ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/category> <https://energy.ld.admin.ch/elcom/electricityprice/category/H4> ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/product> <https://energy.ld.admin.ch/elcom/electricityprice/product/standard> . } } GROUP BY ?operator } } ORDER BY DESC(xsd:decimal(?total))

{{ t "page.energy.consumptionProfiles" "Consumption profiles" }}

{{ tHTML "page.energy.profilesIntro" "Prices are never quoted for a single abstract customer. ElCom defines fifteen standard profiles — H1–H8 for households, from a two-room flat to a large single-family home with a heat pump, and C1–C7 for businesses, from a small workshop to a mid-sized industrial plant. Every profile is priced separately by every operator in every year, which is where the 770,000 observations come from: a few hundred operators multiplied by fifteen profiles, two products and sixteen years." }}

{{ tHTML "page.energy.profilesDefinitions" "Each profile is a SKOS concept in its own right, and it carries its definition with it: a reference consumption in kilowatt-hours per year and a prose description of the household or business it stands for. That is what makes the comparison below meaningful — H4 and H3 both consume 4,500 kWh a year, but H3 is a four-room flat with an electric water heater while H4 is a five-room flat with a tumble dryer and none, so the two are priced against genuinely different customers rather than an arbitrary label." }}

# ?category stays an IRI so the backend resolves and links it. MIN/MAX/AVG across all # operators show how the spread itself changes between household and business profiles. # No ?observation column here: each row aggregates MIN/MAX/AVG over hundreds of # observations, so no single IRI represents it. ?observations counts them instead — # open the linked category to reach the underlying rows. SELECT ?category ?annualKWh ?description ?cheapest ?dearest ?average ?operators ?observations WHERE { { SELECT ?category (MIN(xsd:decimal(?total)) AS ?cheapest) (MAX(xsd:decimal(?total)) AS ?dearest) (ROUND(AVG(xsd:decimal(?total)) * 100) / 100 AS ?average) (COUNT(DISTINCT ?operator) AS ?operators) (COUNT(?obs) AS ?observations) WHERE { GRAPH <https://lindas.admin.ch/elcom/electricityprice> { ?obs <https://energy.ld.admin.ch/elcom/electricityprice/dimension/period> "2026"^^xsd:gYear ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/category> ?category ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/operator> ?operator ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/total> ?total ; <https://energy.ld.admin.ch/elcom/electricityprice/dimension/product> <https://energy.ld.admin.ch/elcom/electricityprice/product/standard> . } } GROUP BY ?category } # ElCom defines each profile as a SKOS concept carrying its reference consumption # (schema:size, kWh/year) and a prose definition. The definition is published in # GERMAN ONLY — there is no en/fr/it variant — so no dispLang filter is applied # here: filtering by language would empty the column for every other visitor. GRAPH <https://lindas.admin.ch/elcom/electricityprice> { OPTIONAL { ?category schema:size ?annualKWh } OPTIONAL { ?category schema:description ?description } } } ORDER BY ?category

{{ t "page.energy.whereTheEnergyComesFrom" "Where the energy comes from" }}

{{ tHTML "page.energy.energyBalanceIntro" "The Swiss energy balance runs from 1980 and reports consumption in terajoules per year, broken down by energy carrier. The carriers come from a shared LINDAS dimension rather than free text, and they nest: renewable splits into wood, hydro and other renewables, non-renewable into nuclear fuels, petrol products, gas, coal and waste. {{ t "page.energy.waterInTheMountains" "Water in the mountains" }}

{{ tHTML "page.energy.reservoirIntro" "Switzerland's alpine reservoirs are the country's battery, and the reservoir filling level cube is the only weekly series in this theme — a reading every Sunday at midnight of how many gigawatt-hours are stored against the maximum the basins can hold. It is a genuinely operational dataset: during the 2022 supply debate this was the number people watched. Two things about its shape are worth knowing before querying it. The regions are not a dimension but separate columns (gr… for Grisons, ti… for Ticino), and the reading date is not a property at all — it survives only inside the observation IRI, so it has to be parsed out of the string before the series can be sorted." }}

# Two quirks of this cube: # 1. The reading date is NOT a predicate — it exists only as the last path segment # of the observation IRI (…/observation/2008-06-02), so it is parsed out here. # There is no temporal dimension to sort or filter on otherwise. # 2. Region is encoded in the property NAME rather than as a dimension value, so # the regions come back as columns instead of rows. # Percentages are computed here because the cube stores only absolute GWh figures. SELECT ?date ?grisonsGWh ?grisonsPercent ?ticinoGWh ?ticinoPercent ?observation WHERE { GRAPH <https://lindas.admin.ch/sfoe/cube> { <https://energy.ld.admin.ch/sfoe/bfe_ogd17_fuellungsgrad_speicherseen/5> cube:observationSet/cube:observation ?observation . ?observation <https://energy.ld.admin.ch/sfoe/bfe_ogd17_fuellungsgrad_speicherseen/grAktuellSpeicherinhaltGWh> ?grisonsGWh ; <https://energy.ld.admin.ch/sfoe/bfe_ogd17_fuellungsgrad_speicherseen/grMaxSpeicherinhaltGWh> ?grisonsMax ; <https://energy.ld.admin.ch/sfoe/bfe_ogd17_fuellungsgrad_speicherseen/tiAktuellSpeicherinhaltGWh> ?ticinoGWh ; <https://energy.ld.admin.ch/sfoe/bfe_ogd17_fuellungsgrad_speicherseen/tiMaxSpeicherinhaltGWh> ?ticinoMax . } BIND (REPLACE(STR(?observation), "^.*/observation/", "") AS ?date) BIND (ROUND(xsd:decimal(?grisonsGWh) * 1000 / xsd:decimal(?grisonsMax)) / 10 AS ?grisonsPercent) BIND (ROUND(xsd:decimal(?ticinoGWh) * 1000 / xsd:decimal(?ticinoMax)) / 10 AS ?ticinoPercent) } ORDER BY DESC(?date) LIMIT 500

{{ t "page.energy.subsidisedSolar" "Subsidised solar" }}

{{ tHTML "page.energy.solarIntro" "The one-off payment for photovoltaic installations (Einmalvergütung) is the federal subsidy for rooftop solar, and its cube is the most directly comparable dataset in this theme: per canton, per year, it records the number of installations, the capacity installed in kilowatts, the francs paid out — and the first two normalised per 100,000 inhabitants. That last pair is the reason a small canton can be compared with Zurich without doing the arithmetic yourself." }}

{{ t "page.energy.buildingsAndScenarios" "Buildings and scenarios" }}

{{ tHTML "page.energy.buildingsScenariosIntro" "Two further families round out the SFOE holdings. The Buildings Programme (Gebäudeprogramm) reports the renovation subsidy in four parallel cubes — applications supported, francs paid out, energy saved and CO₂ avoided, all per measure category and reporting year — so the cost and the effect of the same programme can be read side by side.

About this theme

This theme brings together everything the Federal Chancellery publishes about Swiss politics, and it covers two very different kinds of material. The first is what citizens decided: every popular vote, popular initiative and referendum since 1848 — the question that was put, the day it was held, whether it passed, and how each canton voted. The second is who does the governing: the members of parliament and their parties, the federal government and its departments, the offices beneath them, and the lobbyists with access to the parliament building.

Together they answer the two questions people usually arrive with — what has Switzerland voted on, and how did it turn out? and who holds which office today? The sections below walk through both, starting with how a vote comes about.

Direct democracy: how a vote happens

Swiss citizens do not only elect a parliament; they vote on the laws themselves, several times a year. Two instruments put a question to the people, and telling them apart is the single most useful thing to understand about this data — they run in opposite directions.

Popular initiative

Citizens propose. Gather 100,000 signatures and you can demand a change to the federal constitution, whether or not parliament wants one. Recorded since 1891, and tracked from signature collection through withdrawal or ballot.

Referendum

Citizens object. Parliament has passed a law; 50,000 signatures force it to a public vote before it can take effect. Emergency legislation is covered here too, and follows its own accelerated rules.

Both routes end at the same place: a popular vote. That cube is the centrepiece of this theme — and the richest political dataset in LINDAS. It records not one row per vote but one row per proposal per canton, which is why a few hundred proposals become nearly twenty thousand observations. Each row carries yes and no counts and percentages, turnout, eligible voters, blank and invalid ballots, and the cantonal vote (Standesstimme) that constitutional amendments must also win.

# ?title and ?observation stay IRIs on purpose: the backend resolves each to a label in the # visitor's language, and the table renders resolved IRIs as links to their resource page. SELECT ?date ?title ?yesPercent ?turnout ?observation WHERE { GRAPH <https://lindas.admin.ch/fch/popular-vote> { ?observation <https://politics.ld.admin.ch/political-rights/popular-vote/region> <https://ld.admin.ch/country/CHE> ; <https://politics.ld.admin.ch/political-rights/popular-vote/date> ?date ; <https://politics.ld.admin.ch/political-rights/popular-vote/abstimmungstitel> ?title ; <https://politics.ld.admin.ch/political-rights/popular-vote/jaAnteil> ?yesPercent ; <https://politics.ld.admin.ch/political-rights/popular-vote/stimmbeteiligung> ?turnout . Petitions

The quietest instrument, and the only one open to everyone — no signature threshold, no citizenship requirement, no minimum age. Anyone may petition the federal authorities, who are obliged to take note but not to act.

Elections: filling the National Council

Every four years Switzerland elects the 200 members of the National Council. LINDAS holds the results as five cube families per election year, and together they describe the whole proportional machinery: who stood, on which list, how many votes each list drew, and how seats were finally allocated — including the distribution within joined lists (listes apparentées), a Swiss speciality where small parties pool votes to clear the threshold together.

Who governs: people and institutions

Where the cubes above count votes, this family of graphs names people. Curia Vista is the parliamentary register: every member of the Federal Assembly, living and dead, with their party, their parliamentary group, the committees they sat on and the exact dates of each mandate. Because memberships are modelled as dated roles rather than plain links, you can reconstruct the composition of parliament on any given day.

# ?parliamentaryGroup stays an IRI on purpose: the backend resolves it to a label in the # visitor's language, and the table renders resolved IRIs as links to their resource page. # The chamber split comes from each member's *council* role, not the group role, which # carries no council reference. A member of both chambers would count in each column. SELECT ?parliamentaryGroup ?abbreviation ?founded ?nationalCouncil ?councilOfStates ?members ?seatShare WHERE { { SELECT ?parliamentaryGroup # alternateName and validFrom repeat per language, so SAMPLE keeps one row per group (SAMPLE(?abbr) AS ?abbreviation) (SAMPLE(?validFrom) AS ?validFromSample) (COUNT(DISTINCT ?person) AS ?members) (COUNT(DISTINCT ?personNational) AS ?nationalCouncil) (COUNT(DISTINCT ?personStates) AS ?councilOfStates) WHERE { GRAPH <https://lindas.admin.ch/fch/curia> { ?parliamentaryGroup a schema:ParliamentaryGroup . ?role schema:memberOf ?parliamentaryGroup ; schema:member ?person . OPTIONAL { ?parliamentaryGroup schema:alternateName ?abbr } OPTIONAL { ?parliamentaryGroup schema:validFrom ?validFrom } OPTIONAL { ?councilRoleN schema:member ?person ; schema:memberOf <https://politics.ld.admin.ch/council/N> . BIND (?person AS ?personNational) } OPTIONAL { ?councilRoleS schema:member ?person ; schema:memberOf <https://politics.ld.admin.ch/council/S> . BIND (?person AS ?personStates) } } } GROUP BY ?parliamentaryGroup } # validFrom is a real xsd:dateTime ("1972-01-01T00:00:00"), so YEAR() gives just the year. # Note SUBSTR(?validFromSample, ...) would NOT work here: passing a dateTime to a string # function is a type error, and the endpoint silently returns an unbound column for it. BIND (YEAR(?validFromSample) AS ?founded) # 246 = 200 National Council + 46 Council of States seats BIND (ROUND(?members * 1000 / 246) / 10 AS ?seatShare) } ORDER BY DESC(?members)

Interest ties and lobbying

Members of parliament must declare their outside mandates, and the declarations are published here as links between a person and a lobby organization. The useful detail is that each tie is flagged paid or unpaid, and records the function held — so the table below separates the seats a parliamentarian merely occupies from the ones they chair. The two can diverge sharply: of the twelve people with the most paid ties, some chair almost all of them and others chair one.

# ?person stays an IRI on purpose: the backend resolves it to the person's name and the # table renders it as a link, so no separate name column is needed. SELECT ?person ?party ?bornIn ?presidencies ?paidMandates ?unpaidMandates WHERE { { SELECT ?person (SAMPLE(?partyOrg) AS ?party) (SAMPLE(?birthDate) AS ?birthDateSample) # function/type/1 is "Präsident(in)" — a chair seat rather than plain membership, # which separates sitting on many boards from running them. (COUNT(DISTINCT ?presidencyOrg) AS ?presidencies) (COUNT(DISTINCT ?paidOrg) AS ?paidMandates) (COUNT(DISTINCT ?unpaidOrg) AS ?unpaidMandates) WHERE { GRAPH <https://lindas.admin.ch/fch/curia> { ?paidRole schema:memberOf ?paidOrg ; schema:member ?person ; schema:hasSalary true . ?paidOrg a schema:LobbyOrganization . OPTIONAL { ?person schema:birthDate ?birthDate } OPTIONAL { ?presidencyRole schema:member ?person ; schema:memberOf ?presidencyOrg ; schema:hasSalary true ; schema:additionalType <https://politics.ld.admin.ch/function/type/1> . ?presidencyOrg a schema:LobbyOrganization . } OPTIONAL { ?unpaidRole schema:member ?person ; schema:memberOf ?unpaidOrg ; schema:hasSalary false . ?unpaidOrg a schema:LobbyOrganization . } OPTIONAL { ?partyRole schema:member ?person ; schema:memberOf ?partyOrg . ?partyOrg a schema:PoliticalParty } } } GROUP BY ?person } # birthDate is an xsd:dateTime, so YEAR() gives the year on its own (see the groups # query above: a string function like SUBSTR would silently return an unbound column). BIND (YEAR(?birthDateSample) AS ?bornIn) } ORDER BY DESC(?paidMandates)

Government and administration

Three further registers describe the executive side. The Federal Council graph covers the seven-member government since 1848 — councillors, chancellors, which department each held, who was president in which year, and a curiosity found in few national datasets: the people who were elected and declined. The Staatskalender is the government directory, listing offices with their postal addresses and staff. Extra-parliamentary commissions covers the expert bodies that advise the administration from outside it.

FILTER (?vicePresident != cube:Undefined) } } } ORDER BY DESC(?year)

Parliamentary business

One graph in this theme is modelled quite differently from the rest. Procedural requests — motions, postulates and interpellations through which members of parliament formally ask the government to act — use the PAF ontology, an activity-and-entity model borrowed from provenance vocabularies rather than the cube or schema.org shapes used everywhere else. Each request is an entity; each step in its handling is an activity with its own status text from the administration.

# Each status text is published in de/fr/it, so without a language filter every request # appeared three times. ?request and ?office stay IRIs so the backend labels and links them; # the request IRI ends in /entity, so the affair number is pulled out as a separate literal. SELECT ?affair ?title ?type ?office ?status ?request WHERE { GRAPH <https://lindas.admin.ch/fch/procedural-request> { ?informationEntity a <https://ch.paf.link/ProceduralRequestInformationEntity> ; <https://ch.paf.link/proceduralRequestInformation> ?status . FILTER (lang(?status) = visoto:dispLang) # The activity ties the status text to the request it belongs to. ?activity <http://www.w3.org/ns/prov#used> ?informationEntity ; <http://www.w3.org/ns/prov#used> ?request . ?request a <https://ch.paf.link/ProceduralRequestEntity> ; <https://ch.paf.link/proceduralRequestType> ?type ; <https://ch.paf.link/proceduralRequestTitle> ?title . FILTER (lang(?title) = visoto:dispLang) # The responsible federal office — note this is the office answering the request, # not the parliamentarian who filed it (the submitter is not in this graph). OPTIONAL { ?activity <http://www.w3.org/ns/prov#qualifiedAssociation>/<http://www.w3.org/ns/prov#agent> ?office } BIND (REPLACE(STR(?request), "^.*/parliamentary-affair/([^/]+)/entity$", "$1") AS ?affair) } } ORDER BY ?affair
{{ template "sparqlAsyncTable" (dict "queryId" "politicsProceduralRequests" "title" "Procedural requests — status reports" "icon" "file-text" "collapsed" true) }}

Status texts are published in German, French and Italian, and follow your browser's language here. A single request usually carries several as it moves through the process, so the same title can appear more than once — each row is one report on that request, not one request.
